# AGS 개발 로드맵

## P0 · 개발 기반

이번 소스에는 TypeScript 소스와 빌드된 JavaScript 양쪽으로 실행하는 mock CLI, 공급자 코드, 자동 테스트, Windows/Linux CI가 들어 있다. packages/providers/src/mock.ts가 메시지를 처리하고 scripts/mock.ts가 터미널 입출력을 담당한다. 테스트는 CLI의 종료 상태와 응답, 독립된 두 요청, 공백 입력을 확인한다.

Node 24.22.3과 pnpm 11.25.0은 이 작업 환경에서 설치·실행을 확인한 버전이다. TypeScript 5.9.3과 Biome 2.3.8은 정확한 버전으로 고정했다. CLI 테스트는 Node 내장 테스트 러너를 사용한다. 웹 프레임워크, 서버 라이브러리와 브라우저 테스트 도구는 처음 사용하는 PR에서 선택하고 고정한다. 라이선스는 보류 상태다.

완료 기준은 깨끗한 소스에서 잠금 파일로 설치한 뒤 lint, typecheck, test, build와 빌드된 CLI 실행까지 통과하는 것이다. 운영체제별 결과는 실제 CI 실행 기록에서 확인한다.

## P1 · 독립 채팅

첫 단계의 구현은 Node 내장 HTTP 서버와 합성 mock 공급자를 사용한다. 요청과 이벤트 형식은 [채팅 HTTP 계약](CHAT_API.md)에 있다. GitHub 이슈 #2, #3, #4가 아래 순서에 대응한다.

| 순서 | 범위 | 리뷰에서 재현할 완료 조건 |
|---|---|---|
| 1 | 로컬 HTTP 서버와 mock 채팅 스트림. 텍스트 조각·완료·오류·취소 계약을 정의하고 요청마다 실행을 격리한다. | 두 요청을 동시에 실행하고 하나만 취소해도 다른 응답이 끝까지 도착한다. 중단 후 리소스가 정리된다. loopback 바인딩, 로컬 인증, Origin 검사를 테스트한다. |
| 2 | React 채팅 화면, 프리셋 선택, SQLite 세션 저장. 중앙 입력창에서 전송하고 진행 중 중단할 수 있게 한다. | 합성 프로젝트에서 두 세션을 만들고 대화한다. 중단한 응답 상태가 기록되고 재시작 후 기록과 프리셋이 복원된다. 브라우저에서 전송·중단·복원을 검증한다. |
| 3 | 사용자가 선택한 첫 실제 공급자를 서버 어댑터로 연결한다. 공급자별 스트림과 오류를 공통 계약으로 변환한다. | 모의 공급자 응답으로 정상·실패 경로를 검증하고 키가 브라우저나 로그에 노출되지 않는지 확인한다. 실제 키를 사용하는 1회 왕복은 별도 동의 후 확인하고 결과를 명시한다. |

두 번째 단계는 React와 Vite로 빌드한 화면을 API 서버에서 같은 출처로 제공한다. 세션과 프리셋, 응답 조각과 종료 상태를 Node 내장 `node:sqlite`로 사용자별 비공개 폴더에 저장한다. 브라우저 테스트는 임시 DB를 사용해 서버 재시작 전후의 두 세션과 중단한 턴을 확인한다. #4에서는 공급자 인증 오류, 5xx, 네트워크 실패에서도 응답과 로그에 인증 정보가 남지 않는지 검증한다.

첫 공급자는 OpenRouter이며 사용자 지정 OpenAI 호환 서버도 같은 스트리밍 어댑터를 사용한다. 회귀 검증은 로컬 HTTP fixture로 수행하고 실제 공급자 왕복은 별도 옵트인으로 남긴다. P1의 완료 지점은 독립 세션에서 첫 실제 공급자로 대화하고 재시작 뒤 이어갈 수 있을 때다.

### P2 · 프로젝트 작업공간

프로젝트·섹션·대화의 소속과 등록 폴더는 로컬 DB에 보관한다. 원본 문서는 사용자가 지정한 폴더에 둔다. 프로젝트 화면에서 폴더를 연결하고 목록과 줄 범위를 읽을 수 있다. 연결 폴더 안에서 문구를 검색하고, 검색 당시 버전을 확인한 뒤 해당 줄의 원본을 열 수 있다. 넓은 화면에서는 대화 옆에서 파일을 열고 프로젝트별 활동 기록을 확인할 수 있다. 사용자가 선택한 파일·줄 범위는 대화별로 첨부하고 전송 전에 확인하거나 뺄 수 있다. 승인형 저장을 켠 프로젝트는 단일 텍스트 파일의 생성·수정안을 비교하고 승인할 수 있다. 저장 시 원본 버전을 재확인하고 수정 전 원본을 백업한다. 외부 편집이 감지되면 사용자의 초안을 유지해 새 원본과 비교할 수 있다. 안내도 등 공유 문서도 같은 승인 절차로 작성한다.

P2 완료 시나리오는 배포본의 `examples/P2-workspace/INDEX.md`에서 안내문 원본을 열고 비교·승인해 수정하는 것이다. 브라우저 회귀 테스트에서 승인 전후의 디스크 내용, 새 파일, 충돌, 백업과 활동 기록을 확인한다. 다음 단계인 P3는 섹션 기억 복원과 지식 참조를 다룬다.

### P3 첫 단계 · 섹션 현재 상태 복원

사용자가 작업 폴더에서 목표·결정·다음 행동을 담은 짧은 원본 파일을 섹션에 지정한다. 이후 같은 섹션에서 시작하는 대화는 선택한 버전을 장기기억 블록에서 읽는다. 원본 변경, 섹션 격리, 참조 토글, 입력 예산을 미리보기와 실제 전송에 동일하게 적용한다. 시간순 사건 추출과 구간 요약, 계층형 지식 탐색은 뒤이은 P3 작업이다. 긴 문서의 떨어진 변경 구간을 따로 보여주는 개선은 P6의 파일 비교 화면에서 다룬다.

### P3 · 섹션 대화의 구간 요약

완료 턴의 시간순 구간에서 결정과 미해결 과제를 발췌하는 명시적 체크포인트를 추가했다. 출처를 보며 초안을 고친 뒤 승인하면 원본 턴 범위를 담은 작업 폴더의 파일이 생긴다. 섹션의 최근 요약을 다음 대화에서 복원하며 갱신과 참조 토글을 독립적으로 적용한다. 구간을 넘어서는 장기 압축과 계층형 지식 탐색은 후속 범위다.


### P3 · 계층형 지식 안내도와 대화별 발췌

프로젝트의 `INDEX.md`에서 분야 안내도, 개념 문서, 원본 파일의 줄 범위로 이동한다. 대화에서 쓸 지식은 사용자가 선택한 버전의 발췌로 저장하고, 섹션 기억과 독립된 외부 지식 참조 설정을 미리보기와 실제 전송에 적용한다. 예제는 전시 연표의 날짜를 확인하는 과정을 담는다. 이번 범위는 등록된 프로젝트 폴더를 대상으로 한 수동 탐색이다.

지식 발췌 목록에서 현재 연결된 원본의 버전 일치·변경·확인 불가 상태를 확인할 수 있다. 안내도는 줄 범위 링크와 탭을 오가는 탐색을 지원한다. P3의 원본 변경 감지는 저장 당시 스냅샷을 유지하며, 실제 사용자 폴더와 유료 공급자 회고는 주요 기능을 모은 시점에 진행한다.


### P4 첫 단계 · 독립 검토 대화

사용자가 모델과 보낼 내용을 확인하고 단일 요청을 승인한다. 원래 대화와 분리된 검토 세션을 저장하며 검토 결과의 일부를 입력 초안에 가져오거나 프로젝트 폴더에 승인 후 저장할 수 있다. 외부 모델 간 실사용은 마일스톤 회고에서 확인한다.

P4 실험용 호출 로그는 채팅·독립 검토·구간 요약·모델 목록 조회의 종료 상태와 응답을 대조하고 JSON으로 내보낼 수 있다. 실제 유료 호출 전에도 합성 공급자가 반환한 헤더·SSE 본문·조립된 답변과 오류 응답을 각각 검증한다.

독립 검토에 현재 대화에서 고른 파일·지식 발췌 스냅샷을 첨부할 수 있다. 요청별 검토 이력에서 이전 독립 대화를 다시 열어 전달 내용과 결과를 확인한다.

OpenAI Chat Completions 직접 연결을 추가했다. 공급자별 키·기본 모델·즐겨찾기를 구분하고 채팅·독립 검토·구간 요약·호출 로그에서 같은 공급자 선택을 사용한다. 유료 계정 두 곳의 실제 왕복은 실사용 검증에 남아 있다.

Google Gemini Developer API의 네이티브 스트리밍을 추가했다. 모의 HTTP 공급자로 OpenAI 대화에서 Gemini에 독립 검토를 요청하고 그 결과를 다시 여는 흐름을 검증한다.

Anthropic Messages API를 연결해 세 공식 공급자를 같은 모델 설정·독립 검토·호출 기록에서 사용할 수 있다. Windows 시작 시 저장된 키는 한 번의 DPAPI 프로세스로 복원한다.

### P5 첫 단계 · 로컬 파일 교환과 충돌 복구

외부 편집기나 CLI는 프로젝트에 연결한 폴더에 UTF-8 문서를 작성한다. 사용자는 폴더 목록을 새로고침해 외부 파일을 발견하고 필요한 줄을 첨부할 수 있다. 같은 파일을 양쪽에서 수정하면 최신 원본과 다시 비교하거나 AGS 초안을 같은 폴더의 별도 파일로 승인해 저장한다. 브라우저 테스트는 별도 파일 이름까지 외부 편집기가 먼저 사용한 경우 두 외부 파일과 AGS 초안이 모두 보존되는지 확인한다. 클라우드 저장소 연동과 비공개 상태 백업·복원은 후속 범위다.

### P6 첫 단계 · 비공개 상태 백업과 복원

서버를 종료한 뒤 비공개 DB, 키를 제외한 공급자 설정, 승인형 파일 편집 전의 백업을 파일 하나로 내보낸다. 복원은 백업 형식 및 DB 버전, SHA-256, SQLite 무결성과 외래 키를 검사한 뒤 새 상태 폴더에 게시한다. 연결한 폴더의 쓰기 권한은 다시 승인한다. Windows 배포본 검증에는 임시 상태 백업·복원 후 서버를 다시 여는 과정이 포함된다. 긴 문서의 변경 구간 표시와 좁은 패널 정돈은 다음 P6 범위다.
