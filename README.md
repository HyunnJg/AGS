# AI General Staff (AGS)

여러 AI가 각자의 세션에서 작업하고, 필요할 때 같은 작업공간의 자료와 결과를 주고받는 개인용 로컬 작업환경입니다.

## 지금 실행할 수 있는 것

터미널과 로컬 HTTP 서버에서 mock 공급자에 메시지를 보낼 수 있습니다. HTTP에서는 응답이 조각 단위로 도착하며, 요청 하나를 중단해도 다른 요청은 계속됩니다. 브라우저에서 대화별로 프리셋을 선택하고, 앱을 다시 시작한 뒤에도 대화와 부분 응답을 이어서 확인할 수 있습니다.

## Windows에서 바로 열기

GitHub Actions에서 검증이 끝난 **Verify AGS** 실행의 **AGS-Windows** 아티팩트를 내려받아 ZIP 전체를 풀고 **Start-AGS.cmd**를 두 번 클릭하세요. Node.js 24.22.3 이상 24.x가 필요합니다. 화면 파일이 포함되어 pnpm 설치나 빌드는 생략할 수 있습니다. 서버가 준비되면 기본 브라우저가 열리고 로컬 접속 토큰이 클립보드로 복사됩니다. 토큰을 붙여 넣고 **작업실 열기 → 첫 대화 시작**을 선택하세요. 종료할 때는 콘솔에서 Ctrl+C를 누르세요.

키 없이 시작하면 로컬 mock으로 확인할 수 있습니다. 새 대화는 키와 기본 모델 ID를 함께 등록한 공급자 중 OpenRouter, OpenAI, Google Gemini, Anthropic 순으로 시작합니다. 기존 세션은 마지막으로 저장한 선택을 유지합니다.

### 작업실 백업과 복원

AGS 콘솔에서 Ctrl+C로 서버를 종료한 뒤, 압축을 푼 배포 폴더의 PowerShell에서 아래 명령을 실행하세요. 백업 파일과 복원 폴더는 새 이름을 지정합니다. 상위 폴더는 미리 만들어 두세요.

```powershell
.\Start-AGS.cmd export "$HOME\Documents\작업실-01.ags-backup"
.\Start-AGS.cmd restore "$HOME\Documents\작업실-01.ags-backup" "$HOME\AGS-복원"
$env:AGS_STATE_DIR = "$HOME\AGS-복원"
.\Start-AGS.cmd
```

마지막 두 줄은 복원한 작업실을 여는 명령입니다. 이후에도 이 작업실을 쓰려면 같은 상태 폴더를 지정하세요. 기본 작업실로 돌아가려면 서버를 종료하고 `Remove-Item Env:AGS_STATE_DIR`를 실행한 뒤 다시 시작하세요. 소스 배포에서는 빌드 후 `node dist/scripts/state-backup.js export <새 파일>` 및 `node dist/scripts/state-backup.js restore <백업 파일> <새 폴더>`를 사용합니다.

백업에는 대화, 프로젝트·섹션, 프롬프트와 모델 설정, 첨부 발췌, 호출 로그, 승인형 편집 직전의 원본 사본이 포함됩니다. 평문 파일이므로 비공개 위치에 보관하세요. 등록한 API 키와 Windows에 저장된 암호화 키 값은 제외합니다. 대화·문서에 직접 적은 내용은 그대로 담깁니다. 연결한 프로젝트 폴더의 실제 파일은 따로 복사하세요. 복원 후 **설정**에서 필요한 키를 다시 입력하고 **프로젝트 · 파일**에서 폴더 위치와 승인형 저장 권한을 확인하세요.

### 실험 중 호출 기록 확인

왼쪽 하단 **설정 → 호출 로그**에서 **목록 새로고침**을 누르고 확인할 호출을 고르세요. 채팅, 독립 검토, 구간 요약, 모델 목록 조회가 구분됩니다. **응답 헤더**에는 HTTP 메타데이터가, **응답 본문**에는 수신한 SSE 프레임이나 공급자의 오류 본문이, **최종 답변**에는 화면 표시 규칙을 적용하기 전의 조립한 텍스트가 나옵니다. 실패·중단·시간 초과에는 종료 전까지 받은 답변을 표시합니다. 로컬 mock은 HTTP 응답 없이 결과만 기록합니다.

공급자에게 채팅·검토·구간 요약을 요청하면 **요청 요약**에서 모델, 실제 전송한 메시지 수, 메시지 본문의 UTF-8 바이트 합계와 출력 토큰 한도를 확인할 수 있습니다. 요청 원문은 수집하지 않습니다. 한도를 보내지 않은 호출은 ‘미지정’으로 표시합니다.

공급자 채팅의 **전송 시 입력 구성**에서 당시의 입력 한도와 추정 토큰 수를 볼 수 있습니다. **블록별 입력 예산**을 펼치면 장기기억·직전 대화·검색 자료 중 몇 개의 메시지를 포함했고 예산 때문에 몇 개가 빠졌는지 확인할 수 있습니다. 이후 설정을 바꿔도 이 수치는 호출 당시 값으로 남고, JSON에도 함께 들어갑니다.

**로그 비우기**를 누르고 확인하면 현재 저장된 호출 로그 전체를 삭제합니다. 대화와 새 호출 기록 설정은 유지되며, 진행 중인 호출은 종료 후 기록될 수 있습니다.

**공급자 보고 토큰**에서는 응답에 포함된 입력·출력·캐시 사용량을 AGS 추정치와 함께 확인할 수 있습니다. 보고된 항목만 표시하며 중단된 호출에는 마지막으로 받은 수치가 남습니다.

**이 호출 JSON 다운로드** 또는 **전체 JSON 다운로드**를 누르면 브라우저의 다운로드 설정에 따라 파일을 저장합니다. 로그는 기본으로 켜져 있으며 이 PC의 비공개 DB에 최근 종료된 100건을 보관합니다. **새 호출 기록**을 끄면 이후 시작하는 호출부터 수집을 멈춥니다. 본문은 앞 64 KiB, 답변은 앞 65,536 UTF-16 코드 단위까지 기록하고 잘린 부분을 표시합니다. 인증 키와 쿠키 헤더 값은 가립니다. 내보낸 JSON에는 실제 답변과 공급자 오류 내용이 포함됩니다.

### 다른 모델에 검토 요청

**설정 → 토글형 모듈 → AI 협업 허용**을 켜고, 대화 입력창 위의 **다른 모델에 검토 요청**을 여세요. 검토 모델을 고른 뒤 질문과 전달할 자료를 직접 입력합니다. **마지막 답변 추가**를 누르면 직전 완료 답변을 가져와 보낼 부분만 편집할 수 있습니다. **승인하고 검토 요청**을 누르면 그 내용으로 독립 대화를 하나 만듭니다. API 모델을 고르면 사용료가 발생할 수 있으며, 로컬 mock으로 같은 흐름을 시험할 수 있습니다.

현재 대화에 첨부한 파일이나 지식 발췌가 있으면 **함께 보낼 첨부 자료**에서 필요한 항목만 고르세요. **보낼 내용 미리보기**에서 요청과 발췌 당시 경로·줄 범위·버전·원문을 확인하고 승인합니다. 요청과 발췌를 합쳐 8,000자까지 보낼 수 있습니다. **검토 이력**에서 이전 요청을 고르면 당시 보낸 내용과 결과가 저장된 독립 대화로 이동합니다.

검토 결과에서 필요한 문장만 남기고 **입력창에 추가**를 누르면 원래 대화의 초안 뒤에 붙습니다. 전송은 직접 누릅니다. 전체 결과와 요청은 별도 검토 대화에 남습니다. 승인형 저장을 켠 프로젝트의 섹션에서는 **검토 결과 파일로 저장 → 변경 비교 → 승인하고 저장**으로 공유 폴더에 Markdown 파일을 작성할 수 있습니다.

### 프로젝트와 로컬 작업 폴더

왼쪽 **프로젝트 · 파일**을 열면 넓은 화면에서는 대화 오른쪽에 작업공간이 펼쳐집니다. 파일을 열어 둔 채 메시지를 작성할 수 있습니다. 좁은 화면에서는 대화 위에 작업공간을 엽니다. 여기서 프로젝트를 만들고, 기본 **일반** 섹션이나 직접 추가한 섹션에서 대화를 시작하세요. 같은 메뉴에서 해당 섹션의 대화를 다시 열 수 있습니다. 기존 대화는 왼쪽 대화 목록에 유지됩니다.

**작업 폴더 연결**에 서버 PC의 프로젝트 폴더 절대 경로를 입력하고 **읽기 전용 연결**을 누르세요. 폴더와 `INDEX.md` 같은 UTF-8 텍스트 파일을 탐색하고, 시작 줄을 지정해 한 번에 80줄씩 볼 수 있습니다. 연결 정보는 로컬 DB에 저장됩니다. 파일은 프로젝트의 각 섹션에서 함께 열어볼 수 있고, 미리보기 내용은 모델에 자동 전송되지 않습니다. 기존 프로젝트에서도 **연결 폴더 변경**을 열어 저장 권한을 바꿀 수 있습니다.

**P2 예제를 실행하려면** 압축을 푼 폴더에서 `examples/P2-workspace`의 절대 경로를 복사하세요. **프로젝트 · 파일**에서 프로젝트를 하나 만들고 해당 경로를 입력한 뒤 **승인형 저장 허용 → 승인형 저장으로 연결**을 누르세요.

1. **INDEX.md → 전시 안내 초안**을 눌러 안내도가 가리키는 원본을 엽니다.
2. **파일 수정**에서 안내문을 고치거나 현재 대화의 마지막 답변을 초안으로 가져옵니다. **변경 비교**에서 원본과 수정안의 줄 번호를 확인합니다. 떨어진 변경 사이에는 그대로인 줄 수가 표시됩니다. 변경이 많아 구간을 나누기 어려운 경우에는 해당 범위의 원본과 수정안 전문이 표시됩니다.
3. **승인하고 저장**을 누르면 원본이 바뀝니다. 직전 원본의 백업 파일명은 **활동 기록**에 표시되며 백업은 서버 상태 폴더의 `backups`에 있습니다. 원본이 먼저 바뀌면 **최신 원본과 다시 비교**로 초안을 유지한 채 변경분을 다시 확인합니다.

폴더 목록의 **새 파일**에서도 이름과 본문을 정하고 같은 방식으로 승인할 수 있습니다. UTF-8 텍스트 파일은 1 MiB까지 편집할 수 있습니다. 새 파일 생성에는 하드링크를 지원하는 파일 시스템(예: NTFS)이 필요합니다.

**외부 편집기·CLI와 파일을 주고받을 때**는 연결한 작업 폴더에 UTF-8 문서를 저장하세요. AGS에서 해당 폴더의 **폴더 목록 새로고침**을 누르면 추가되거나 삭제된 파일을 확인할 수 있습니다. 작성 중인 새 파일의 이름과 초안은 유지됩니다. 자료를 모델에 보내려면 사용할 줄 범위를 대화에 첨부하세요.

같은 원본을 양쪽에서 수정했다면 **최신 원본과 다시 비교**로 외부 변경을 확인하세요. 두 버전을 모두 남기려면 **초안을 다른 이름으로 저장 → 변경 비교 → 승인하고 저장**을 선택하세요. 같은 폴더에 새 파일이 생깁니다. 다른 도구가 그 이름을 먼저 사용한 경우 **수정안 편집**에서 이름을 바꾼 뒤 다시 비교할 수 있습니다.

같은 섹션의 새 대화에 목표와 결정을 이어주려면 예제의 **INDEX.md → 전시 준비 현황**을 열고 **섹션 현재 상태 → 현재 파일을 상태로 지정**을 누르세요. **섹션에서 새 대화**를 열고 **설정 → 모델 → 컨텍스트 제어 → 전송 미리보기**에서 장기기억 블록을 펼치면 어떤 내용이 들어가는지 확인할 수 있습니다. 원본이 달라졌다면 최신 파일을 열고 다시 지정하세요. **설정 → 토글형 모듈 → 섹션 기억 참조**에서 모든 섹션의 상태 참조를 켜거나 끌 수 있습니다.

**지식 안내도에서 근거 고르기**. 대화를 열고 **프로젝트 · 파일 → 지식 안내도**로 들어가세요. 예제에서는 **전시 자료 조사 방법 → 전시 연표의 날짜 검토 → 대조할 원본 기록**을 누르면 원본 3–4줄이 선택됩니다. **첨부 시작 줄·끝 줄**을 고르고 **지식 발췌 추가**를 누르면 해당 범위의 사본이 현재 대화의 검색·임베딩 자료 블록에 들어갑니다. 문서를 열어 보는 동안에는 대화 입력이 바뀌지 않습니다.

자기 폴더에서는 최상위 `INDEX.md`에서 분야별 Markdown 문서로 상대 링크를 걸고, 개념 문서에서 원본 파일로 연결하세요. `[원본](../notes/register.md#L3)`처럼 시작 줄을 지정하거나 `#L3-L4`로 발췌 범위를 지정할 수 있습니다. 대화의 **첨부 자료**에서 경로·범위·버전을 확인하고 뺄 수 있습니다. **설정 → 토글형 모듈 → 외부 지식 참조**를 끄면 저장한 지식 발췌는 보관되며, 이후 요청에서 제외됩니다. 일반 파일 첨부와 섹션 기억은 각각의 기존 설정을 따릅니다.

**첨부 자료**를 펼치면 지식 발췌의 저장 버전과 현재 연결 폴더의 같은 경로에 있는 문서 전체를 비교합니다. 확인 시각과 결과를 표시하며, 문서를 편집한 뒤에는 **원본 다시 확인**으로 갱신할 수 있습니다. 원본이 변경되거나 사라져도 이전 발췌는 보관됩니다. 교체하려면 원본을 열어 새 범위를 확인하고 이전 발췌를 뺀 뒤 다시 추가하세요. 작업공간 안에서 파일·활동 기록 탭을 오갈 때는 지식 안내도의 읽던 위치와 이전 문서 목록이 유지됩니다.

**대화에서 구간 요약 남기기**. 승인형 저장으로 연결한 프로젝트의 섹션에서 대화를 연 뒤, 입력창 위 **구간 요약 → 요약 초안 만들기**를 누르세요. 로컬 mock 예제에는 `결정: 개막일은 토요일`과 `다음: 관람 시간 확인`을 한 메시지에 적어 보세요. 실제 모델을 선택하면 버튼에 표시된 공급자로 아직 기록하지 않은 완료 턴을 최대 8개 보냅니다. 질문과 답변은 각각 앞 3,000자까지 사용합니다.

**요약에 사용한 대화**에서 근거를 확인하고 초안을 고친 뒤 **승인하고 요약 저장**을 누르세요. 작업 폴더에 원본 턴 범위를 포함한 Markdown 파일이 생깁니다. 같은 섹션의 새 대화는 현재 상태와 최근 구간 요약 3건을 입력 예산 안에서 참고합니다. **토글형 모듈 → 작업기억 갱신**을 끄면 새 요약 만들기와 승인이 중지됩니다. 저장한 요약을 참고할지는 **섹션 기억 참조**에서 따로 설정합니다.

**파일 내용 검색**에서 문구를 입력하면 일치한 줄의 경로와 발췌문이 나옵니다. 결과를 누르면 해당 줄부터 원본이 열립니다. 검색은 기본으로 대소문자를 무시하며, 정확한 표기가 필요하면 **대소문자 구분**을 켜세요. 원본이 바뀌면 다시 검색하거나 **최신 파일 1줄부터 열기**로 현재 내용을 확인하세요. 기본 범위는 연결한 폴더 전체이며, 하위 폴더를 열면 검색 범위를 그 폴더로 좁힐 수 있습니다. `.git`, `node_modules`, `dist`는 자동으로 건너뜁니다.

파일에서 **첨부 시작 줄·끝 줄**을 고르고 **현재 대화에 첨부**를 누르면 그 시점의 발췌문이 저장됩니다. 입력창 위 **첨부 자료**에서 내용을 확인하거나 뺄 수 있습니다. 첨부만으로는 모델을 호출하지 않습니다. 이후 이 대화에서 전송할 때 입력 예산 안에서 **검색·임베딩 자료** 위치에 포함됩니다. 원본을 수정해도 이미 첨부한 내용은 유지됩니다.

**활동 기록**에서 이 프로젝트의 최근 폴더 탐색·파일 읽기·검색·첨부·생성·수정 100건을 확인할 수 있습니다. 성공한 조회에는 상대 경로와 읽은 줄 범위가, 실패한 조회에는 오류 사유가 남습니다. 본문과 검색어는 기록에 저장하지 않습니다.

## 실제 모델 연결

왼쪽 하단 **설정 → 모델 → 공급사 · 모델**에서 **OpenRouter**, **OpenAI**, **Google Gemini**, **Anthropic (Claude)** 또는 **사용자 지정 API**를 선택하세요. **연결 설정**에 API 키를 입력하고 **연결 저장**을 누르면 모델 목록이 열립니다. 원하는 모델을 고른 뒤 **선택 모델을 기본값으로 저장**하면 해당 공급자의 기본 모델로 등록됩니다. 모델 ID를 알고 있다면 첫 연결 때 함께 입력할 수도 있습니다. OpenAI 호환 서버는 API 기본 주소도 입력하세요. 키가 필요 없는 로컬 서버는 키를 비워 두세요.

OpenAI를 선택하면 공식 API 주소가 자동으로 적용됩니다. 계정의 모델 목록에서 Chat Completions를 지원하는 텍스트 모델을 고르세요. OpenAI 직접 연결의 최대 출력 토큰에는 추론 토큰도 포함됩니다. **설정 → 호출 로그 → 응답 본문**에서 공급자가 스트림 끝에 반환한 `usage`를 확인할 수 있습니다.

Google Gemini에서는 Gemini Developer API 키를 입력하고 모델 목록에서 텍스트 생성 모델을 고르세요. 직접 입력할 때는 `models/` 뒤의 모델 ID를 사용합니다. 시스템 지침과 대화 순서를 보존하며, 호출 로그의 응답 본문에서 공급자가 보낸 `finishReason`과 `usageMetadata`를 확인할 수 있습니다.

Anthropic (Claude)에서는 워크스페이스 전용 Claude API 키를 등록하고 모델을 고르세요. 최대 출력 토큰을 비운 일반 채팅의 기본 한도는 4,096, 독립 검토는 1,200입니다. 검토 이력에서 승인한 요청과 결과를 다시 열 수 있습니다.

Windows에서 입력한 키는 현재 사용자 계정의 DPAPI로 암호화해 저장합니다. 다른 운영체제에서는 입력한 키가 서버를 종료할 때까지 유지되며, 주소와 기본 모델은 재시작 후에도 남습니다. 키를 교체하려면 새 값을 입력하세요. 키만 지우려면 **저장 시 기존 키 제거 → 연결 저장**을 누르세요. 주소를 바꿀 때는 새 서버에 사용할 키를 지정하거나 기존 키 제거를 선택하세요.

서버 환경 변수로 초기값을 지정할 수도 있습니다. 화면에서 저장한 주소와 모델이 우선하며, 기존 키를 유지하면 같은 주소의 환경 변수 키를 계속 사용합니다.

| 공급자 | 서버 환경 변수 |
|---|---|
| OpenRouter | `AGS_OPENROUTER_API_KEY`와 선택 사항인 `AGS_OPENROUTER_MODEL` |
| OpenAI 직접 연결 | `AGS_OPENAI_API_KEY`와 선택 사항인 `AGS_OPENAI_MODEL` |
| Google Gemini 직접 연결 | `AGS_GEMINI_API_KEY`와 선택 사항인 `AGS_GEMINI_MODEL` |
| Anthropic 직접 연결 | `AGS_ANTHROPIC_API_KEY`와 선택 사항인 `AGS_ANTHROPIC_MODEL` |
| 사용자 지정 OpenAI 호환 API | `AGS_CUSTOM_BASE_URL` (예: `http://127.0.0.1:8080/v1`), 선택 사항인 `AGS_CUSTOM_API_KEY`, `AGS_CUSTOM_MODEL` |

좌측 하단 **설정**에서 공급자와 모델을 관리합니다. **모델 → 공급사 · 모델**에서 공급자를 고르고, 이름이나 ID로 검색해 **적용**하세요. 공급자별 기본 모델과 별표로 등록한 모델은 모든 대화의 입력창 아래에 한 번씩 표시됩니다. 독립 검토에서도 연결된 공급자의 같은 모델을 고를 수 있습니다. 다른 탭에서 기본 모델이나 연결 설정을 바꿨다면 채팅 탭으로 돌아올 때 선택지가 갱신됩니다. 현재 대화의 모델은 입력창 아래에서 직접 전환할 수 있습니다. 목록을 제공하지 않는 서버는 모델 ID를 직접 입력할 수 있습니다. OpenAI 호환 서버는 지정된 기본 URL 뒤에 `/chat/completions`를 붙입니다. 원격 주소는 HTTPS를 사용합니다. 메시지를 보내면 기본으로 해당 세션의 최근 완료 대화 최대 12턴이 포함됩니다. A 대화에서 응답이 진행 중이어도 B로 전환해 별도 요청을 보낼 수 있습니다.

**설정 → 모델 → 컨텍스트 제어**에서 현재 대화에 포함할 최근 완료 턴 수(0~64), 입력 예산 및 최대 출력 토큰을 저장하세요. 0턴은 이전 대화 없이 현재 요청을 보냅니다. 입력 예산은 UTF-8 바이트 수와 메시지당 여유분을 이용한 보수적 추정입니다. 서버가 조회한 모델의 컨텍스트 길이가 있으면 지정한 출력 공간도 남깁니다. 지침과 현재 메시지가 남은 예산을 넘으면 전송 전에 알려줍니다.

**설정 → 모델 → 정규식**에서 모델 답변에 적용할 표시 규칙을 위에서 아래 순서로 배치하세요. 예를 들어 패턴 `^초안: *`과 빈 치환문을 저장하면 `초안: 첫 답변`이 화면에 `첫 답변`으로 보입니다. 테스트 문장에서 먼저 확인하거나 답변 아래 **원문 보기**로 전환할 수 있습니다. 저장 기록과 다음 요청은 원문을 사용합니다. 치환문은 `$&`(전체 일치), `$1`~`$99`(캡처), `$$`(달러 기호)를 지원합니다. 규칙 실행이 250ms를 넘거나 길이·치환 횟수 한도를 넘으면 원문을 표시합니다.

**전송 미리보기**는 현재 입력창 초안과 화면의 컨텍스트 설정으로 메시지 구성을 로컬에서 보여줍니다. **블록별 입력 예산**을 펼치면 전송 순서대로 블록별 추정 토큰, 포함한 메시지 수, 입력 예산 때문에 빠진 메시지 수를 볼 수 있습니다. 입력 한도가 있으면 남거나 초과한 양도 표시합니다. 예산을 바꿔 다시 미리볼 수 있으며, **저장**한 뒤 다음 요청부터 적용됩니다. **공용 프롬프트**의 지침은 모든 세션에 적용되며, 미리보기에서 고정 규약과 분야 프리셋 사이에 들어가는 내용을 확인할 수 있습니다. 응답을 받는 동안에도 설정을 열 수 있습니다.

**설정 → 모델 → 분야 프리셋**에서 UTF-8 Markdown 파일을 가져오거나 지침을 직접 입력하세요. 이름과 본문을 확인하고 **프리셋 등록**을 누르세요. 바로 아래 **등록된 프리셋**에서 이름을 펼치면 저장된 지침을 읽을 수 있습니다. 적용할 때는 해당 대화 상단의 **프리셋**에서 선택합니다. 예컨대 역사 해석에 쓸 영문 지침을 등록하고 응답 언어를 한국어로 지정할 수 있습니다. 원본을 수정한 뒤 새 버전을 쓰려면 다른 이름으로 등록하세요. 이전 판본을 펼쳐 **프리셋 보관**을 누르면 다른 대화의 선택 목록에서 숨겨집니다. 그 판본을 쓰던 대화는 같은 지침으로 계속 진행됩니다. 다시 쓰려면 같은 자리에서 **선택 목록에 복원**을 누르세요.

**설정 → 언어 지원 → 기본 응답 언어**에서 한국어·영어·일본어·중국어(간체·번체)를 골라 저장하면 다음 공급자 채팅과 독립 검토에 적용됩니다. 특정 요청에서만 다른 언어가 필요하면 메시지에 직접 지정하세요. 기본값인 **자동**은 언어 지침을 생략합니다. **고정 지침 미리보기**에서 전송할 문장을 확인할 수 있습니다.

**공용 프롬프트 → 컨텍스트 주입 순서**에서 장기기억, 직전 대화, 검색·임베딩 자료, 현재 입력을 원하는 순서로 배치합니다. 공용 지침의 줄바꿈은 전송할 때도 유지됩니다. 고정 지침은 항상 맨 앞에 들어갑니다. 기본 순서는 장기기억 → 직전 대화 → 검색 자료 → 현재 입력입니다. 자주 바뀌는 입력을 뒤에 두는 캐시 친화적인 기본 배치이며 실제 재사용은 공급자에 따라 달라집니다.

**컨텍스트 제어 → 이 대화의 참고 자료**에서 장기기억 메모와 검색 결과를 직접 저장할 수 있습니다. 자동 기억 생성과 벡터 검색은 후속 기능입니다. 빈 자료는 생략하고, 예산으로 빠진 자료는 전송 미리보기에서 확인합니다.

**고급 기능**에서 현재 대화 저장 폴더와 응답 시간 제한을 확인합니다. 서버 시작 전 `AGS_IDLE_TIMEOUT_MS`(기본 60초)와 `AGS_TIMEOUT_MS`(전체 상한, 기본 10분)를 밀리초 단위로 지정할 수 있습니다. Windows에서 여러 Node 버전을 사용할 때는 `node -v`로 확인하고 지원 버전인 24.22.3 이상 24.x 셸에서 실행하세요.

## 설치와 첫 실행

Node.js 24.22.3과 pnpm 11.25.0을 사용합니다. Windows PowerShell과 Linux 셸에서 저장소 루트로 이동한 뒤 실행하세요.

```sh
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev "첫 작업 확인"
```

출력은 `[mock] 수신한 메시지: 첫 작업 확인`입니다. 인자를 생략하면 기본 예문으로 실행합니다.

## 웹 작업실 열기

위 설치를 마쳤다면 PowerShell에서 다음을 실행하세요. 로컬 접속용 토큰은 클립보드로 복사됩니다.

```powershell
pnpm build
$env:AGS_LOCAL_TOKEN = node -p "require('node:crypto').randomBytes(32).toString('hex')"
Set-Clipboard -Value $env:AGS_LOCAL_TOKEN
pnpm server:start
```

브라우저에서 서버가 표시한 주소(기본 `http://127.0.0.1:4317`)를 열고 토큰을 붙여 넣으세요. **첫 대화 시작**을 누른 뒤 메시지를 보냅니다. Enter는 전송, Shift+Enter는 줄바꿈입니다. 긴 응답 도중 **중단**을 누르면 받은 부분이 저장됩니다. **새 대화**에서 다른 프리셋을 선택해 독립적으로 작업할 수 있습니다.

로컬 mock은 공급자 키 없이 프리셋과 응답 형식을 확인할 때 사용합니다. 브라우저는 로컬 토큰을 현재 탭의 sessionStorage에 보관합니다. 서버에서 토큰을 교체하면 새 값으로 다시 연결하세요.

대화 DB는 기본적으로 사용자 홈의 `.ags/private/sessions.sqlite`에 저장합니다. 다른 위치로 지정하려면 시작 전 `AGS_STATE_DIR`를 설정하세요. 한 데이터 폴더를 서버 하나가 사용하며, Ctrl+C로 종료합니다. 강제 종료된 응답은 다음 시작 시 받은 부분까지 복원하고 중단 상태를 표시합니다.

## 로컬 채팅 서버 실행

Windows PowerShell에서 아래 세 줄을 실행하면 같은 셸에 임시 토큰을 두고 서버를 시작한 뒤 첫 응답을 확인할 수 있습니다.

```powershell
$env:AGS_LOCAL_TOKEN = node -p "require('node:crypto').randomBytes(32).toString('hex')"
$agsServer = Start-Process node -ArgumentList 'apps/server/src/main.ts' -NoNewWindow -PassThru
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:4317/api/chat -Headers @{ Authorization = "Bearer $env:AGS_LOCAL_TOKEN" } -ContentType 'application/json' -Body '{"message":"hello"}'
```

서버가 주소를 출력한 뒤 마지막 줄을 실행하세요. 종료할 때는 `Stop-Process -Id $agsServer.Id`를 사용합니다.

Linux 셸에서는 다음과 같이 실행합니다.

```sh
export AGS_LOCAL_TOKEN="$(node -p "require('node:crypto').randomBytes(32).toString('hex')")"
node apps/server/src/main.ts &
ags_pid=$!
# 서버 주소가 출력된 후 요청합니다.
curl -N http://127.0.0.1:4317/api/chat -H "Authorization: Bearer $AGS_LOCAL_TOKEN" -H 'Content-Type: application/json' -d '{"message":"hello"}'
kill "$ags_pid"
```

전경 실행 명령은 `pnpm server`이며, 빌드 후에는 `pnpm server:start`를 사용할 수 있습니다. 기본 포트는 4317입니다. 포트를 변경할 때는 `AGS_PORT`를 지정하고 클라이언트 주소에도 적용하세요. 브라우저 연동과 요청 중단 방법은 [채팅 HTTP 계약](docs/CHAT_API.md)에 있습니다.

## 검증과 빌드

```sh
pnpm run check
pnpm start "빌드 실행 확인"
```

`check`는 린트, 타입 검사, 자동 테스트, 빌드, 빌드한 서버의 실제 HTTP 왕복 테스트를 순서대로 실행합니다. `start`는 빌드된 JavaScript를 실행합니다. GitHub Actions에서도 Windows와 Linux에 같은 절차를 적용합니다.
